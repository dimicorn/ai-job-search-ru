# Если сломалось

Начните с проверки — она покажет, что не так, и подскажет, как починить:

```bash
uv run hh-agent doctor            # быстро, без сети
uv run hh-agent doctor --online   # ещё вход на hh.ru, Хабр и в Telegram и тестовый запрос к LLM
```

## Где смотреть

| Что | Где |
|---|---|
| Все события: поиск, оценка, отклики, капчи, вызовы LLM, опросы ботов | `logs/events.jsonl` |
| Сводка по журналу | `uv run hh-agent stats`, `uv run hh-agent report --days 7` |
| Вывод запуска по расписанию | `logs/autopilot.log` |
| Вопросы, на которые агенту не хватило фактов | `logs/questions.md` |
| Нераспознанные формы и сбои отклика: страница, фрагмент формы, скриншот, причина | `debug/<id>.*`, для Хабра — `debug/habr/` |
| Скриншоты пробного прогона | `screenshots/` |
| Подстройка темпа | `learned.json` (удалите, чтобы сбросить) |

## Частые ситуации

### Капча

Агент капчу не решает. В `auto` и `autopilot` он присылает уведомление macOS, выводит вкладку
с капчей вперёд и ждёт `apply.auto.captcha_wait_minutes` (по умолчанию 15 минут). Не прошли —
на этом сайте до конца запуска остановка, вакансия остаётся в очереди. Если браузер запущен без
окна (`browser.headless_apply: true`), пройти капчу нельзя — агент сразу останавливается.
После капчи агент сам делает паузы длиннее (`learned.json`). Капчи часто подряд — уменьшите
`apply.daily_limit` и `apply.auto.max_per_run` или увеличьте паузы в `apply.auto`.

### Слетел вход на hh.ru, Хабр Карьеру или в Telegram

`doctor --online` покажет ✗ у входа. Выполните `uv run hh-agent login` в обычном терминале.
Без входа на Хабр вакансии оттуда уходят в `manual` с причиной «нет входа в Хабр Карьеру».
Чтобы войти в Telegram заново (другой аккаунт, сброс сессии), удалите `.telegram.session`
и выполните `login`.

### «Браузер агента занят другим запуском hh-agent — жду…»

Профиль браузера открывается только в одном процессе: второй запуск ждёт первого (до 3 часов).
Обычно это autopilot по расписанию. Дождитесь его или остановите (Ctrl+C в его терминале,
`launchctl stop ru.hh-agent.autopilot` для расписания).

### «Telegram-сессия занята другим запуском hh-agent»

Опросы ботов идут только в одном процессе: два подключения с одной сессией Telegram рвут друг
друга (в логе — «Server replied with a wrong session ID»). Агент пропустит опросы и пройдёт их
в следующий раз. Не запускайте `hh-agent recruiters` во время `autopilot`.

### Кончились лимиты LLM

С запасной LLM (`analyst.fallback_backend`) агент сам переходит на неё до времени сброса лимита
из ответа (у Codex — «try again at 4:37 PM») и потом возвращается. Время сброса хранится
в `.llm-limits.json`: удалите файл, чтобы сразу снова пробовать основную. Без запасной оценка
и письма останавливаются («Лимит исчерпан, остановка»), опросы ботов откладываются до следующего
запуска («Лимит LLM — продолжу в следующий раз»), а вакансии с анкетами уходят в `manual`.
Подробнее — [Какая LLM](llm.md).

### Вакансии в `manual`

`uv run hh-agent list manual` — что отложено и почему. Частые причины:

- **Тест или анкета, где не хватило фактов** — вопрос записан в `logs/questions.md`. Допишите ответ
  в `questions.facts` в `config.yaml` и верните вакансии в очередь: `uv run hh-agent requeue --all`.
- **Форма не распознана** — снимок в `debug/`. Пройдите такие вакансии сами:
  `uv run hh-agent review --manual`.
- **Отклик на сайте компании** — откликнитесь там; в `review --manual` агент откроет сайт
  и скопирует письмо в буфер обмена.

### Отправка не подтвердилась

`uv run hh-agent list unconfirmed` — отклики, после которых агент не увидел подтверждения.
Проверьте их на сайте в разделе откликов; снимок формы — в `debug/`.

### Поиск ничего не находит или все отклики падают

Скорее всего, сайт поменял разметку. Признаки: `scan` находит 0 вакансий при непустой выдаче
на сайте, растёт число снимков в `debug/`, в журнале много ошибок подряд. Проверьте разбор
на свежих страницах:

```bash
uv run python tests/fixtures/refresh.py   # снять образцы с живых сайтов
uv run pytest tests/test_parsing.py       # упавший тест покажет, какое поле агент не находит
```

Не можете починить сами — откройте issue и приложите вывод `doctor` и упавший тест.

### autopilot по расписанию не запускается

- `launchctl list | grep hh-agent` — задача включена? Нет — последний шаг `./setup.sh`.
- `logs/autopilot.log` — ошибки запуска.
- При закрытой крышке Mac спит и задача не запускается; если Mac спал в назначенное время,
  она запустится при пробуждении.
- Агент работает только в `apply.auto.active_hours` (по умолчанию 8:00–23:00) и не больше
  `apply.daily_limit` откликов в сутки — вне этого он только ищет и оценивает.

### Агент «завис»

Пока идёт `scan`, `auto`, `autopilot` или `review`, Mac не засыпает от бездействия, но закрытая
крышка всё равно его усыпляет — агент продолжит после пробуждения. Долгие паузы между откликами
(1.5–4 минуты, перерыв 15–30 минут после каждых 5) — это нормально: так агент меньше похож на бота.

## Сообщить о проблеме

Откройте issue в репозитории: шаблон попросит вывод `uv run hh-agent doctor`, `hh-agent --version`
и кусок `logs/events.jsonl`. Перед отправкой уберите из лога личные данные — тексты писем
и ответов работодателям.
