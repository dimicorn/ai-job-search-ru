# Автоматические отклики

```bash
uv run hh-agent auto --dry-run   # пробный прогон: заполнит 3 формы и сделает скриншоты в screenshots/, ничего не отправит
uv run hh-agent auto             # отклики без подтверждения, по правилам из apply.auto в config.yaml
uv run hh-agent autopilot        # поиск, оценка, отклики и Telegram параллельно — для запуска по расписанию
```

Паузы (все случайные): 8–20 с «чтения» вакансии с прокруткой, 0.8–2.5 с между кликами,
письмо вставляется в поле целиком, 1.5–4 мин между откликами,
перерыв 15–30 мин после каждых 5 откликов. Работает только с 8:00 до 23:00,
не больше 10 откликов за запуск и 20 в сутки. 3 ошибки подряд на сайте → на нём остановка.

Всё идёт параллельно в одном браузере, у каждой части своя вкладка и свой поток:

- **поиск и оценка** (только `autopilot`): поиск на hh и Хабре одновременно, затем оценка
  и письма — LLM получает до `analyst.parallel` (по умолчанию 3) запросов сразу;
- **отклики на hh** и **отклики на Хабре** — независимо, у каждого сайта свои паузы и ошибки.
  Отклики начинаются сразу с готовой очереди, а новые вакансии подхватываются по мере оценки;
- **Telegram** — опросы AI-рекрутеров, заново после новых откликов в их компании;
- **поднятие резюме** (только `autopilot`) — «Поднять в поиске» на hh.ru для всех видимых
  работодателям резюме, если с прошлого поднятия прошло 4 часа. Выключается `apply.raise_resume: false`;
  вручную — `uv run hh-agent raise`.

Для каждого сайта темп прежний, а общий прогон занимает меньше времени: этапы больше не ждут
друг друга. Дневной лимит и лимит запуска общие для обоих сайтов. Добор до нормы
(`daily_target`) вакансиями с баллом ниже `min_score` начинается, когда поиск закончен
и сильных вакансий на сайте не осталось.

Капчу агент сам не решает. Если сайт её показал, придёт уведомление macOS, вкладка с капчей
выйдет вперёд, и агент до 15 минут (`apply.auto.captcha_wait_minutes`) ждёт, пока вы её пройдёте.
Другой сайт и Telegram в это время работают дальше. Пройдёте — проверит отклик и продолжит;
не пройдёте — на этом сайте остановится, вакансия останется в очереди.
Вакансии с тестами и анкетами уходят в `list manual`. Отклики с неподтверждённой отправкой — в `list unconfirmed`.

В `--dry-run` агент всё равно нажимает «Откликнуться». Если hh в этот момент сразу отправляет
отклик (бывает при одном резюме), отклик уходит, и агент дописывает письмо.

## Остановка

Ctrl+C останавливает запуск аккуратно: новых откликов и опросов агент не начинает, паузы обрывает,
выводит итог (сколько откликов, сегодня всего), пишет его в журнал и подстраивает темп, как после
обычной сессии. Браузер при Ctrl+C сразу закрывается, поэтому отклик, который шёл в этот момент,
обрывается и остаётся в очереди (если он всё же ушёл, в следующий раз агент это увидит). Ответ
боту в Telegram после Ctrl+C не уходит — опрос продолжится в следующий раз. Второй Ctrl+C — выйти сразу.

`kill` (SIGTERM) и `launchctl stop` останавливают так же, но текущий отклик агент доделывает.

## Каждый день по расписанию

На macOS `autopilot` можно запускать каждый день через launchd (шаблон —
`launchd/ru.hh-agent.autopilot.plist`). Если Mac в это время спал, задача запустится при
пробуждении. При закрытой крышке не запускается. Лог пишется в `logs/autopilot.log`.

Включается на последнем шаге `./setup.sh` (он спросит час). Дальше:

```bash
launchctl start ru.hh-agent.autopilot                                  # запустить прямо сейчас
launchctl unload ~/Library/LaunchAgents/ru.hh-agent.autopilot.plist   # выключить
```

Пока autopilot работает (около 2–3 часов), не запускайте `review`: профиль браузера
открывается только в одном процессе.

## Подстройка и отчёт

После каждой сессии с откликами агент подстраивает темп простыми правилами (без LLM),
значения — в `learned.json`:

- капча → все паузы в 1.25 раза длиннее (множитель не больше 3);
- три спокойные сессии подряд (отклики были, ни капчи, ни ошибок) → паузы чуть короче, но не короче базовых;
- отправка не подтвердилась (не из-за капчи) → ждать подтверждения на 5 с дольше (до 30 с);
- форма отклика не распознана → ждать форму на 5 с дольше (до 30 с).

Лимиты, пороги, запросы и фильтры меняете только вы в `config.yaml`. Каждое событие пишется в
`logs/events.jsonl`, нераспознанные формы и сбои — снимками в `debug/`: по ним чинят код.
`uv run hh-agent report [--days 7]` — сводка и рекомендации по журналу за период (один вызов LLM).
Чтобы сбросить подстройку, удалите `learned.json`.
