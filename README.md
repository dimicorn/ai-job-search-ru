# hh-agent: агент откликов на hh.ru и Хабр Карьере

С 15.12.2025 hh.ru закрыл API для соискателей, поэтому агент работает через ваш браузер
(Playwright с отдельным профилем, где хранится сессия hh.ru). Откликаться можно
с подтверждением каждого отклика (`review`) или автоматически (`auto`). Кроме hh, агент ищет и откликается на
[Хабр Карьере](https://career.habr.com/vacancies) — см. раздел ниже.

```
 Разведчик (scout)    →  Аналитик (Codex)          →  Вы (review)        →  Исполнитель (applier)
 выдача hh по          оценка 0–100, причины,        [y] / правка /          заполняет форму,
 фильтрам + локальные   red flags, письмо              переписать / skip       жмёт «Отправить»
 стоп-слова
```

## Установка

```bash
cd ~/hh-agent
uv sync && uv run playwright install chromium
cp config.example.yaml config.yaml    # фильтры
cp resume.example.md resume.md        # текст резюме для оценки и писем
codex login                           # если Codex CLI ещё не авторизован
```

Оценка и письма по умолчанию идут через Codex CLI (`codex exec`) по вашей подписке ChatGPT,
отдельно платить не нужно. Бэкенд меняется в `config.yaml`: `analyst.backend` — `codex`,
`claude_code` (`claude -p`, подписка claude.ai) или `api` (Claude API по `ANTHROPIC_API_KEY`).
`analyst.letter_backend: codex` — письма пишутся отдельным запросом и только для вакансий
с проходным баллом.

## Использование

```bash
uv run hh-agent login      # один раз: войти в hh.ru (и Хабр Карьеру, если она есть в searches)
uv run hh-agent scan       # найти вакансии и оценить их
uv run hh-agent letters    # переписать письма для оценённых вакансий
uv run hh-agent review     # пройтись по подходящим и откликнуться
uv run hh-agent run        # scan + review
uv run hh-agent stats
uv run hh-agent list manual   # что требует ручного отклика (тесты, анкеты)
```

### Хабр Карьера

Поиск с `source: habr` (или с `url` на career.habr.com) идёт по Хабр Карьере, остальные — по hh.
Параметры те же, что в адресе страницы `career.habr.com/vacancies`: `q`, `s[]` (специализации),
`qid` (уровень, одно значение), `remote`, `locations[]`, `salary`, `with_salary`, `sort`. Пример есть
в `config.example.yaml`. Выдача читается через JSON API сайта (25 вакансий на странице), описание берётся
со страницы вакансии. Фильтры, оценка, письма, лимиты и `review`/`auto` общие для обоих сайтов.
В `list` есть колонка «сайт».

- `hh-agent login` по очереди откроет вход на каждый сайт из `searches`. На Хабр Карьеру
  входят через Хабр Аккаунт.
- На Хабре отклик уходит **сразу** по кнопке «Откликнуться». Письмо агент дописывает следом
  в форме «Дополнить отклик». Поэтому `auto --dry-run` на Хабре ничего не нажимает, только делает скриншот.
  При `submit_mode: manual` «Откликнуться» и «Дополнить отклик» нажимаете вы, агент только вписывает письмо.
- Если вакансия принимает отклики на сайте компании, она уходит в `manual`. В `review` агент откроет
  этот сайт и скопирует письмо в буфер обмена.
- Если нет входа на один из сайтов, `review` и `auto` пропускают его вакансии и работают с остальными.
- Нераспознанные формы Хабра сохраняются в `debug/habr/`. `learn` их не разбирает:
  он учит селекторы только для hh.

### Автоматические отклики

```bash
uv run hh-agent auto --dry-run   # пробный прогон: заполнит 3 формы и сделает скриншоты в screenshots/, ничего не отправит
uv run hh-agent auto             # отклики без подтверждения, по правилам из apply.auto в config.yaml
uv run hh-agent autopilot        # scan + оценка + auto — для запуска по расписанию
```

Паузы (все случайные): 8–20 с «чтения» вакансии с прокруткой, 0.8–2.5 с между кликами,
письмо вставляется в поле целиком, 1.5–4 мин между откликами,
перерыв 15–30 мин после каждых 5 откликов. Работает только с 9:00 до 21:00,
не больше 10 откликов за запуск и 20 в сутки. Капча, 3 ошибки подряд → остановка.
Вакансии с тестами и анкетами уходят в `list manual`. Отклики с неподтверждённой отправкой — в `list unconfirmed`.

В `--dry-run` агент всё равно нажимает «Откликнуться». Если hh в этот момент сразу отправляет
отклик (бывает при одном резюме), отклик уходит, и агент дописывает письмо.

### Каждый день по расписанию

`launchd/ru.hh-agent.autopilot.plist` запускает `autopilot` каждый день в 10:00. Если Mac
в это время спал, задача запустится при пробуждении. При закрытой крышке не запускается.
Лог пишется в `logs/autopilot.log`.

```bash
sed "s|__HOME__|$HOME|g" launchd/ru.hh-agent.autopilot.plist > ~/Library/LaunchAgents/ru.hh-agent.autopilot.plist
launchctl load ~/Library/LaunchAgents/ru.hh-agent.autopilot.plist      # включить
launchctl start ru.hh-agent.autopilot                                   # запустить прямо сейчас
launchctl unload ~/Library/LaunchAgents/ru.hh-agent.autopilot.plist    # выключить
```

Пока autopilot работает (около 2–3 часов), не запускайте `review`: профиль браузера
открывается только в одном процессе.

### Вопросы работодателя

Если в форме отклика есть вопросы (в окне отклика или на отдельной странице теста), агент
сам разбирает форму: текстовые поля, выбор одного варианта, несколько галочек, списки.
Вопросов может быть сколько угодно или не быть вовсе. Ответы пишет Codex по резюме,
вакансии и фактам из `questions.facts` в `config.yaml`, от вашего имени и без выдумок.

Если нужен личный факт, которого нет в фактах (срок выхода, аккредитация, причина поиска),
`auto` откладывает отклик в `manual`, а вопрос записывает в `logs/questions.md`.
Допишите ответ в `questions.facts` и выполните `hh-agent requeue --all`.
В `review` агент показывает все ответы и спрашивает перед отправкой.

### Непрерывное обучение

После каждой сессии (`auto`, `autopilot`, `review`, `run`) агент сам выполняет `hh-agent learn`:

1. **debug/**. Каждая форма, которую агент не смог разобрать, сохраняется как HTML,
   фрагмент формы и скриншот. LLM определяет тип формы и предлагает селекторы для поля письма и кнопок.
   Каждый селектор проверяется на сохранённом HTML. Прошедшие проверку попадают в `learned.json`,
   а вакансия возвращается в очередь (не больше двух повторов). Если это анкета работодателя,
   вакансия уходит в manual. Обработанные снимки переносятся в `debug/processed/`.
2. **Логи.** События всех сессий (`logs/events.jsonl`) и строки с ошибками из `logs/autopilot.log`
   разбираются LLM. Отчёт с наблюдениями и рекомендациями дописывается в `logs/insights.md`.
3. **Подстройка** в жёстких рамках. Множитель пауз — от 1 до 3, после капчи пауз становится только больше.
   Таймауты — 8–30 с. Число откликов за запуск может только уменьшаться относительно `config.yaml`.
   Пороги, запросы и фильтры автоматически не меняются: это рекомендации для вас.

У каждого выученного селектора ведётся счёт успехов и неудач. Тот, что проваливается раз за разом,
отключается сам. Чтобы сбросить всё выученное, удалите `learned.json`.

Кнопки в review: `y` — откликнуться, `e` — править письмо в `$EDITOR`, `r` — переписать
с указанием («короче», «упомяни проект X»), `o` — открыть вакансию в браузере,
`s` — пропустить навсегда, `l` — отложить, `q` — выйти.

## Что важно знать

- `login`, `review` и `run` интерактивные: запускайте их в обычном терминале.
- **Риск для аккаунта.** Автоматизация браузера противоречит правилам hh.ru. Паузы, рабочие часы
  и лимит (`daily_limit`) снижают риск, но не убирают его полностью; в `auto` он выше, чем в `review`.
- Если форма не распознана или на вопрос работодателя не хватает фактов, в `review` агент копирует
  письмо в буфер обмена и передаёт управление вам, а в `auto` откладывает вакансию в `manual`.
- `submit_mode: manual` — агент только заполняет форму, а «Отправить» вы нажимаете сами.
- Фильтры проще всего настроить на сайте и вставить URL поиска в `searches[].url`.
- Профиль браузера нельзя открыть в двух процессах: второй запуск ждёт, пока первый закончит.
- Вакансия попадает в базу один раз. Чтобы переоценить её после правки резюме:
  `sqlite3 hh_agent.db "update vacancies set status='new' where status='scored'"` и `hh-agent analyze`.
